# 34. 後回しにした別目レビュー指摘の置き場

**状態（2026-10-13）: 全13件 = open 6 / 不明 4 / 解消 3。要対応: D-003〜D-006（#64 の指摘原文の捜索。担当 em-builder、期限 2026-10-19）。EM の対応は不要。**

別目（別の目＝実装者とは別のレビュー担当）の指摘を「今回は直さない」と決めたとき、件数だけでなく中身をここに残す。
board の notes や作業ログに「L1〜L7 は後回し」とだけ書くと、後で中身が追えなくなるため（emh-063 で確認）。

## 1. 書き方

後回しにした指摘を1件1行、下の表に足す。**足すのはマージ前**（PR 本文または別目の返信に残っている間に写す）。

| 列 | 内容 |
|---|---|
| ID | `D-<連番>`。欠番を詰めない |
| 出典 | PR 番号と board の項目 ID（例 `#58 / emh-047`）、重大度（HIGH/MEDIUM/LOW/L番号） |
| 指摘 | 何がどう問題か。1文。原文が復元できなければ「不明」と書き、推測で埋めない |
| 後回しの理由 | 直さなかった理由。理由が不明なら「不明」 |
| 拾う条件 | どうなったら直すか（例「同じファイルを触るとき」）。無ければ「条件なし（未割当。割当は 2026-10-19 の捜索結果後に em-lead が判断）」 |
| 状態 | `open` / `解消（PR 番号）` / `不明` |

- 解消したら行を消さず、状態を `解消（#NN）` にする
- ID は欠番を作らない（1から連番。テストで検査）
- 判断した人・出典が分からない理由は「出典不明」と書く
- `L1`〜`L8` は #64 の別目が付けた指摘番号（Low＝軽微の意）。`O2` は 1on1 の前回アクション追跡機能（設計書 12・32）
- 実データ・個人名・社名は書かない（`scripts/check_no_leak.py`＝実データ混入チェックの対象）
- 重大度が HIGH の指摘は後回しにしない（直す）。ここに載せるのは MEDIUM 以下
