- D7 は**判断材料の整理まで**。持ち越しをどうするか・何を drop するかは EM が決める

## 入力と出力
入力は `tasks.json` と、候補の件数用に `candidates.json`（emh-071。無ければ 0 件）。数え方は `history` の今日付けの操作と現在の状態から（EM の手入力なし）。

| 項目 | 数え方 |
|---|---|
| 今日の完了 | `history` に今日付けの `done`（件数のみ） |
| 持ち越し | open/doing・`due` が今日以前・今日先送りしていない。日数は `due` との差のみ。理由は推測しない |
| 今日先送りした | 今日付けの `defer` |
| 今日動いた返信待ち | waiting で、今日付けの `wait`/`delegate` がある **または `updated` が今日**。`apply_reply`（[24](24-reply-apply.md)）は `wait`/`delegate` を履歴に書かないため後者でも拾う。ただし `updated` は確認予定日の変更でも動くので「新規」とは言い切れず、見出しは「新規を含む」とする |
| 確認予定を過ぎた返信待ち | waiting で `next_check` が今日以前（今日動いたものを除く）。催促の下書きは朝の計画に任せ、夕方は存在を見せるだけ |
| 明日の計画の種 | `due` が明日の open/doing、`next_check` が明日の waiting |
| 判断依頼 | `defer` が 2 回以上（次が 3 回目）。選択肢は drop / 分割。朝と同じ基準（[17](17-task-priority-and-waiting.md)） |

- `next_check` が未設定の waiting は「確認予定未設定」と表示する（落とさない）
- `snooze_until` が未来のものは除外（朝と同じ）。各節は最大 5 件、超過は「ほか N 件」
- 結論: 🔴 持ち越しあり / 🟡 先送り・返信待ち・判断依頼あり / 🟢 それ以外
- 出力は標準出力の Markdown 1 枚。**観察のみで解釈は出さない**（人の評価に当たる出力を持たないため、[14](14-output-quality-checklist.md) の B〜D は「解釈を載せない」ことで満たす）

### 出し方（Q-029 b）に決定、EM・2026-10-11）
- 持ち越し・新しい返信待ち・判断依頼のどれかがある日だけ全文を出す。それ以外は 1 行: `🟢 対応不要（出す内容なし）`。確認予定超過・今日先送りの件数がある時だけ「。確認予定超過 N 件・今日先送り N 件は明朝の計画へ」を足す（0 件なら足さない）
- 未確認の候補（`candidates.json` の snooze 外）がある日は件数だけ 1 行足す（emh-071。本文・件名は出さない・0 件なら何も足さない）。全文の日は「未確認の候補: N 件」、1 行の日は「。未確認の候補 N 件は明朝の計画へ」。**候補だけでは全文の条件にならない**（Q-029 b のまま）。採用/却下/後では朝の計画（[15](15-morning-plan.md)）
- `candidates.json` が壊れている・形式不正のときは候補を 0 件として扱い、stderr に警告を出して締めは止めない（`tasks.json` の不正は従来どおり停止）
- 先送りだけ・確認予定超過だけの日も 1 行になる（催促の下書きは朝の計画が拾う）。`--always` で常に全文
- 1 行は SKILL 手順 2 の自己点検（状態語・対応不要）を満たす

## 朝との違い
朝は「今日やる順」を決める。夕方は「今日どうなったか」を数え、明日に持ち越すものを EM が手放せる状態にする。並べ替えと催促の下書きはしない（朝の仕事）。
