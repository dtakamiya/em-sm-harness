# Jira 接続設計（初版ドラフト・実接続はしない）

状態: ドラフト。**実接続は EM 本人の明示 GO まで行わない。**

## 認証
- API トークン方式。トークンは**環境変数**で渡す（値はコード・設計書・コミット・ログに出さない）
  - `JIRA_BASE_URL` / `JIRA_USER_EMAIL` / `JIRA_API_TOKEN`（Cloud: Basic 認証 email:token。Data Center の PAT なら Bearer。要確認）
- トークンの権限は**読み取りのみ**のアカウント/スコープを推奨。最小のプロジェクト範囲に限定
- ログ・エラー出力にトークン・Authorization ヘッダを出さない（マスク）

## 取得範囲（読み取り専用）
- 対象: 指定プロジェクト/ボードの、現行スプリントと直近 N スプリントの課題
- 取得フィールド（最小）: key / summary / status / assignee / issuetype / priority / created / updated /
  story points（カスタムフィールド ID は設定ファイル化）/ sprint / flagged / issuelinks（blocks）/ status 遷移履歴（changelog）
- 取得しないもの: コメント本文・添付・個人の詳細プロファイル（必要になったら別途設計・承認）

## 取得方式
- JQL 検索 + ページネーション。`updated >= <前回同期>` の差分取得
- 結果は `data/jira-cache/<project>/<YYYY-MM-DD>.json` に保存（gitignore）。スキルはキャッシュを読む
- 同期はコマンド明示実行（自動常駐・定期実行はしない。cron 化は別判断）

## レート制御・失敗時
- 429 は `Retry-After` に従い指数バックオフ（上限回数あり）。連続失敗で中断し、取得済み分は保持
- 401/403 は即中断し「トークン失効/権限不足」と表示（再試行しない）
- 部分取得の場合は出力に「取得範囲が不完全」と明記し、指標を断定しない

## 書き込み
- なし。将来 Jira 書き込み（コメント・ステータス変更）が必要になった場合は、別設計書で
  「ドライラン → 差分表示 → 本人承認 → 実行」の承認制として設計する

## 実装段階
1. インターフェース（`JiraSource`）+ モック実装（`data/` の架空 JSON を返す）
2. キャッシュ読み取り型のスキル（モックで動作確認）
3. 実 HTTP 実装（**GO 後のみ**）。接続テストは読み取り 1 クエリから
