状態: ドラフト（実装済み: scripts/sprint_planning.py・実接続なし）。値はすべて架空例。**S2** = 秘書の仕事の番号（[12](12-secretary-job-list.md) §3.2）。**emh-054** = この設計の backlog ID。**EM** = エンジニアリングマネージャー（利用者）。**SP** = ストーリーポイント（見積もりの相対値）。**N** = 候補の件数。**S4** = チーム向け状況サマリ・**S5** = スコープ変更判断（どちらも 12 §3.2）。**22** = [指標定義](22-jira-metrics-catalog.md)・**31** = [スプリント健全性の型](31-sprint-health-template.md)。🟡 = 注意の状態語。**complete: false** = Jira キャッシュの取得が途中で切れている印（[06](06-cache-schema.md)）。**14 の A〜E** = [出力品質チェックリスト](14-output-quality-checklist.md)の区分。**P1〜P6** = §6 の検証項目の番号。

## 結論
- S2 は「候補一覧」と「容量の材料」を**事実と目安だけ**で出す。**何 SP 入れるか・何を入れるかは出さない**（決めるのは EM とチーム。新規コミットは EM 本人・14 E2）
- 容量の材料は「過去の完了 SP の幅（最小〜最大）」と「繰り越し件数」と「EM が貼った稼働日数」の 3 つ。**平均・予測値・達成率は出さない**（22 §2.2⑤。成績表や約束に読まれるため）
- 出力の先頭に必ず「容量は目安であり約束ではない」を置く（固定文言・§3）
- 担当者別の容量・個人別の過去実績は作らない（14 D3・22 §2.5）。チーム単位のみ
- 実装は別項目。§7 の Q-035・Q-036 は EM 回答済み（どちらも a)、2026-10-11）

## 1. 入力
| 入力 | 元 | 使う項目 | 備考 |
|---|---|---|---|
| 候補課題 | Jira キャッシュ最新（[06](06-cache-schema.md) §2） | `key` / `status_category` / `priority` / `story_points` / `sprints[]` / `flagged` / `links[]` | 候補 = 現在 active スプリントに属さず `status_category != done` の課題。`summary` は既定 `null`（Q-008）なので**キーだけで出す** |
| 繰り越し | 同上 | `sprints[]` が複数 かつ 未完了（22 §2.3 の繰り越し） | 候補の中で別枠表示 |
| 過去の完了 SP | 同上 + `data/structured/` の集計値（保持 90 日・Q-007） | 終了済みスプリントごとの完了 SP 合計（`status_category = done` の SP。`null` 除外・`0` 含む） | キャッシュは 14 日で消えるため、前回までの合計は structured の集計値から読む。**個人別・課題別は持ち込まない**（06 §4） |
| 稼働日数 | EM が貼る 1 行（例: 「次スプリントの稼働日: 9 日、祝日 1 日」） | 日数のみ | **人別の休暇は入力にしない**（個人の勤怠は不要・D3）。無ければ「稼働日数: 未入力」と出す |
| ブロッカー | 同上 | 22 §2.4（`flagged` または blocks の inward で塞ぐ側が未完了。塞ぐ側が取得範囲外なら「状態不明」） | 候補の備考に「ブロッカー有」/「ブロッカー状態不明」（事実で書く） |

- 幅は**直近 3 件の終了済みスプリント**から出す。**3 件に満たなければ幅を出さず**件数のみ（K = 3 固定。少数の幅は代表値に読まれるため。22 §1 の N < 5 より緩い 3 にしたのは、2 週間スプリントなら 5 件で約 10 週間かかり試用が遅れるため。3 は初期値。Q-035 a) で確定）
- 前提: 「終了済みスプリントごとの完了 SP 合計」は [06](06-cache-schema.md) §4 に定義済み（`--history` で渡す。無ければ「過去スプリント 0 件」として件数のみ出る。この集計値を書き出す工程は実接続のフェーズで別項目）
- `complete: false` のときは固定文言（§3 先頭）と「再取得が必要」の 2 つだけを出す

## 2. 出力する項目
| 枠 | 内容 | 出所 |
|---|---|---|
| 目安の注記 | 固定文言（§3） | — |
| 候補一覧 | 優先度順（`priority` → 繰り越し → キー順）。1 件 = キー・`priority`・SP（`null` は「未見積もり」）・備考（ブロッカー有・繰り越し）。**最大 10 件、超過は件数のみ**（14 A2） | jira |
| 見積もり状況 | 候補 N 件のうち SP 未見積もりの件数（件数のみ。N = 候補の件数） | jira |
| 容量の材料 | 直近 3 件の完了 SP の**最小〜最大**、繰り越し件数、稼働日数（EM 入力） | structured / EM 入力 |
| 限界 | 1 行（取得完全か・過去スプリント件数・SP の粒度） | — |

出さないもの: 合計 SP の「推奨」・「入れられる量」・計画 pt と達成率（22 §2.2⑤）・平均や中央値・担当者別の容量・個人名・順位・「今回は X 件が妥当」という文。

## 3. 固定文言（誤読対策）
- 先頭: 「容量は過去の実績から見た目安で、約束ではありません。入れる量と中身は EM とチームが決めます」
- 幅の直後: 「過去 {K} 件の完了 SP の最小〜最大です。予測ではありません（SP はチーム内の相対値で、課題の大きさ・休暇・見積もりの粒度で変わります）」
- 稼働日数は幅を日数で補正しない（補正すると予測値に読まれる）。過去スプリントの稼働日数は入力にしないので「過去と異なる」の比較文言は出さない。限界の行に「幅は稼働日数で補正していません」と常に添える

## 4. 誤読リスクと対策
| リスク | 対策 |
|---|---|
| 幅の上端が「目標」に読まれる | 平均・中央値を出さない。上端だけを強調しない（最小〜最大を同じ行に） |
| 容量が約束としてチームや上長に伝わる | 先頭の固定文言。S4（チーム向けサマリ）に S2 の幅を流用しない |
| 完了 SP の幅が個人やチームの成績表に読まれる | 達成率・計画 pt を出さない。チーム単位のみ・個人別の履歴を持たない |
| SP 未見積もりの候補が「軽い」と読まれる | 「未見積もり N 件」を別に出す。合計 SP は出さないので、未見積もりが幅に含まれないことを限界の行に明記 |
| 過去の幅が少数で偏る | 3 件未満は幅を出さず件数のみ。限界に件数を出す |
| 優先度順が EM の優先順位判断の代わりになる | 「Jira の `priority` の並びで、EM の優先順位ではありません」を候補一覧の見出しに添える |
| 繰り越しを「失敗」と読む | 繰り越しは件数のみ。理由は書かない（Jira から分からない・確認先は担当者） |

## 5. 出力の型（実装出力と一致・架空例）
```
🟡 S2 プランニング材料: 候補 8 件（未見積もり 2 件）。入れる量は EM が決める
容量は過去の実績から見た目安で、約束ではありません。入れる量と中身は EM とチームが決めます

- EX-206 highest 8SP（繰り越し） ／ EX-201 high 5SP（繰り越し） ／ EX-202 high 3SP ほか 5 件（詳細に）
容量の材料
- 過去 3 件の完了 SP: 18〜26（予測ではありません） ／ 繰り越し 2 件 ／ 稼働日数: 9 日（EM 入力）
EM がやること: 候補と材料を見て入れるものを決める。判断依頼: なし
限界: 完了 SP は終了済みスプリント 3 件・SP なしは除外（未見積もりは幅に含まれない）・幅は稼働日数で補正していません・取得完全
```
