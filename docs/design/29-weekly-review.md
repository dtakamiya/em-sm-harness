用語: **L0** = 読み取り専用（何も書き込まない。[03](03-secretary-model.md) の委任ラダーの最下段）/ **D8** = [12](12-secretary-job-list.md) §3.1 の仕事番号 / **トークン** = Jira 等の API 認証値（このフェーズでは取得も使用もしない）

## 結論
- [04](04-personal-tasks.md) の「週次」行（完了数・繰り越し・waiting の滞留を要約。数と事実のみ）を、金曜用の 1 枚にした: `skills/weekly-review/SKILL.md` + `scripts/weekly_review.py`（D8）
- L0。`data/`・Jira・Confluence・Slack への書き込みも送信も、トークン使用もしない。tasks への反映は EM の返答 → 定型語 → [24](24-reply-apply.md)
- 数と事実のみ。評価語・解釈・理由の推測・人別の集計は出さない。レトロ準備（[12](12-secretary-job-list.md) S 系・emh-008）とは別物で、こちらは EM 個人のタスクの週まとめ

## 入力と出力
週 = 月曜から今日まで（金曜に実行する想定。他の曜日でも月曜からの途中経過として動く）。数え方は `history` の日付と現在の状態から（EM の手入力なし）。

| 項目 | 数え方 |
|---|---|
| 完了 / 追加 / 先送り操作 | 週内の `done` / `add` / `defer` の件数（先送りは操作回数） |
| 未完了と持ち越し | 未完了 = open/doing。持ち越し = そのうち週の前に `add` されたもの。理由は推測しない |
| 期限超過 | open/doing で `due` が今日より前。日数は `due` との差のみ（今日期限は含めない） |
| 週内に繰り返し先送り | 週内の `defer` が 2 回以上の open/doing。事実として並べるだけ（判断依頼は朝・夕の仕事。[25](25-evening-wrapup.md)） |
| 返信待ちの滞留 | waiting 全件。「返信待ちにして N 日」は `wait`/`delegate` の最後の操作日からの日数。記録が無ければ「記録なし」と書き、推測しない。確認予定超過と未設定の件数を別に出す |

- `snooze_until` が未来のものは除外（朝・夕と同じ）。各節は最大 5 件、超過は「ほか N 件」
- 結論: 🔴 期限超過あり / 🟡 確認予定超過・未設定の返信待ち、または週内に繰り返し先送りあり / 🟢 それ以外
- 出力は標準出力の Markdown 1 枚。**観察のみ**。人の評価に当たる出力を持たないため、[14](14-output-quality-checklist.md) の B〜D は「解釈を載せない」ことで満たす

## 夕方の締めとの違い
夕方は「今日どうなったか」を数え、明日の種を出す。週次は「今週の合計と、残っているもの」を数える。催促の下書き・並べ替えはしない。

## 受け入れ基準
- [14](14-output-quality-checklist.md) A2: 「詳細」を除く本文は **600 字未満**（テストで確認。架空 1 週間のサンプルで 472 字）。各節は最大 5 件
- 評価語（遅れ・怠・優秀など）が出力に含まれない（テストで確認）
- 主要な振る舞いをテスト 15 件で固定（週の境界・完了・追加・先送り・持ち越し・期限超過の境界・返信待ち 2 種・記録なし・snooze・サンプル一致・5 件超・空の週・非破壊・欠損ファイル）
