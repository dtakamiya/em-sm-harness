# EM の返答を data/tasks に反映する（emh-035 / Q-028 回答 a）

状態: 実装済み（`scripts/apply_reply.py`、テスト `tests/test_apply_reply.py`）。ローカルのみ。Jira / Confluence / Slack へは書かない。
- **emh-035** = board の改善タスク ID（「返答を tasks に反映する手段」）。**Q-028** = 相談キューの質問番号。EM は 2026-10-05 に「a) 秘書が返答を反映してよい（更新前後を監査ログに残し、戻せること・ローカルのみ）」と回答済み（[open-questions](open-questions.md)）

## 結論
- 返答の書式は**定型語 + id**。**開発側（em-harness）の仮決定**（2026-10-05）。マージ後に EM が使った FB（[feedback-inbox](feedback-inbox.md)）で調整する。自由文は秘書が定型語に直し、実行前に EM へ見せる。曖昧なら実行しない
- 書込は委任ラダー L1 の範囲内。個人タスクの更新は policy 上 `task.update`（承認不要の L0 扱い、監査は取る）。外部ツールへは何も出ない（L2 は不要）
- 更新前後は `data/audit/` に残し、直前の反映は `--undo` で戻せる

## 書式（1返答 = 1引数、引用符で囲む）
| 返答 | 動作 | 結果の1行（例） |
|---|---|---|
| `採用 c-0001` | 候補 → 新規 `open` タスク（新 id、期限は候補の `suggested_due`、priority は `soon`） | `+ t-0004 障害振り返りの日程を調整する（期限 10/12）（c-0001 から採用）` |
| `却下 c-0002` | 候補を消し、出典を `rejected.json` に記録（反映側は記録のみ。同じ出典の再提案は取り込み側が止める） | `✗ c-0002 却下（出典を記録。同じ出典は再提案されません）` |
| `後で c-0003 [日付]` | 候補を残し、`snooze_until`（既定は翌日）まで朝の計画から外す | `💤 c-0003 10/6 まで非表示` |
| `完了 t-0001` | `done`。`next_check` は null | `✓ t-0001 完了` |
| `先送り t-0001 2026-10-16` | `due` 変更。3回目で中止か分割かを促す | `→ t-0001 期限 10/9→10/16（3回目） ※先送りが続いています。中止 t-0001 か 分割 t-0001 案1 案2 かを決めてください` |
| `中止 t-0001 [理由]` | `dropped`（04 の drop）。`next_check` は null。理由は空白なし 1 語で `history` に残す。判断依頼はこれで消える | `✗ t-0001 中止` |
| `分割 t-0001 案1 案2 …` | 親を `dropped`（`history` に op=split）にし、案ごとに新規 `open` タスクを作る（2〜5 件・空白なしのタイトル、期限・優先度は親を引き継ぐ、notes に分割元）。監査は `new_task_ids` | `✂ t-0001 を分割 → t-0004 調査 / t-0005 実装` |

- 実行: `python3 scripts/apply_reply.py "採用 c-0001" "完了 t-0002"`。確認だけなら `--dry-run`
- 全件を検証してから書く。1件でも不正（id 不一致、閉じたタスク、日付の誤り）なら tasks は変更しない
- id は完全一致のみ。タイトルから探す場合は秘書が候補を提示し、EM が id を選ぶ
- `--undo` と返答の同時指定、`--undo` と `--dry-run` の同時指定（取り消しは確認なしで実行されるため）、`--force` 単独はエラー
- 形式が不正な JSONのうち、トップレベルの形式（オブジェクトで、対象キーが配列）と各要素の `id` 欠落（`rejected` を除く）だけを検査し、不正なら上書きせずエラーメッセージで止まる。それ以外のフィールド欠落・型不正は検査しない

## 記録と取り消し
- 監査: `data/audit/YYYY-MM-DD.jsonl` に操作ごと1行。`event=task_updated`、`actor=secretary`、`op`、`target_id`、`changes`（実際に変わったファイルごとの前後 `sha256`。採用は tasks.json と candidates.json、却下は candidates.json と rejected.json）、採用時は `new_task_id`。**同一 `batch_id` 内の前後ハッシュは、その操作単体ではなくバッチ全体（1回の呼び出し）の反映前後の値**（同じファイルを複数操作が変えれば、各行に同じ値が入る）。取り消しは `event=task_reverted`。**タスク本文は入れない**（[05](05-approval-and-audit.md) §3）
- 監査ログに書けない場合は、書込前の確認で止める。ただし確認後〜追記までの間に失敗する窓は残る（その場合は tasks が更新済みで監査行が欠けるため、エラー終了（終了コード 2）し、`--undo` で戻す）
- 取り消し用: 反映前の `tasks.json` / `candidates.json` / `rejected.json` を `.bak` に退避し、`.last-reply.json` に**反映前・反映後のハッシュ**を持つ。`.bak` を先に、マニフェストを次に、本体を最後に書く
- `--undo` は何も触る前に全 `.bak` の存在と反映前ハッシュを照合し、1つでも合わなければ何もせず拒否する（失敗した反映の古い `.bak` で「戻した」と偽らない）。手編集（反映前でも後でもない内容）も拒否（`--force` で上書き）。戻せるのは直前の1回のみ
- 原子性は**ファイル単位**（一時ファイル → rename）。3ファイルをまたぐ一括の原子性はない。途中で落ちたら、反映前・後が混在した状態から `--undo` で反映前へ戻せる
- 壊れた JSON は上書きせず `.bak` 復元を提案して止まる
- `rejected.json` は反映側では**記録のみ**。再提案を止める参照側は取り込みスクリプト（`slack_to_candidates.py` / `meeting_to_candidates.py`）が実装済みで、同じ `source_ref` は候補にしない

## 受け入れ基準
- 5種の返答が動く / 不正は全件拒否 / 監査に本文なし / `--undo` で全ファイルが元のバイト列に戻る
- 異常系: 途中クラッシュ後の undo・`.bak` 欠落・`.bak` 不一致・監査不可・手編集後の undo
- `python3 -m unittest discover -s tests` で通る（`tests/test_apply_reply.py`）

## 候補 id の採番

候補 id（`c-0001`〜）は採用・却下で `candidates.json` が空になっても再利用しない。取り込み（`slack_to_candidates.py` / `meeting_to_candidates.py`）は採番済みの最大番号を `tasks/candidate-seq.json` に残し、次は「現存候補の最大番号」と「記録済みの最大番号」の大きい方 + 1 から振る。記録が無い・壊れているときは現存候補の最大番号から振る。`--dry-run` は番号を消費しない。
