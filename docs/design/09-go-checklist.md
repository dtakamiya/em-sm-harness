## C0. 最重要条件: トークンは Claude から見えない
EM 回答により必須。設計への帰結:
- トークンを使う取得処理は **EM が自分のターミナルで直接実行**する（Claude セッションの外）。Claude Code の Bash は親プロセスの環境変数を引き継ぐので、**トークンを export したシェルから Claude を起動しない／Claude セッション内で取得コマンドを走らせない**
- Claude が読むのは取得結果（`data/` のキャッシュ＝必要項目のみ）だけ。トークン値・Authorization ヘッダ・認証付き URL は結果にもログにも含めない
- 実行コマンドは EM 側に準備済みのものを使う（本 repo では実装しない・値も扱わない）。再構築側は「そのコマンドが出力する形式」を入力契約として受ける
- Claude の権限設定で Keychain 参照コマンド（`security find-generic-password` 等）と認証情報ファイルの読み取りを deny しておく（会社 Mac 側の設定。要 EM 確認）

## C. トークンの発行と保管（A3・B 通過後）
**発行（EM 本人が実施。秘書・Ryoko は取得しない）**
1. 発行元の管理画面でトークンを新規作成（用途名は汎用名。有効期限は組織ポリシー内の最短を選ぶ）
2. 発行直後の表示は 1 回限り。**チャット・メモ・repo・シェル履歴に貼らない**
3. 発行日・期限・失効手順を EM の手元（repo 外）に記録

**保管（macOS Keychain 推奨）**
- 登録: `security add-generic-password -s <サービス名> -a <アカウント名> -w`（`-w` に値を直書きせず、プロンプト入力にする＝シェル履歴に残さない）
- 取得は実行時に `security find-generic-password -s <サービス名> -a <アカウント名> -w` で行い、環境変数に載せる範囲を当該プロセスだけに限定
- シェル rc（`.zshrc` 等）・`.env` へ平文で置かない（`.env*` は gitignore 済みだが、それに頼らない）
- サービス名・アカウント名も会社固有情報を含めない命名にする（実名は `config/local.*` 側）

**失効・ローテーション**
- 期限前の更新日を EM のカレンダーに入れる（秘書は下書き提案のみ）
- 漏えいの疑い・退職/異動・PC 紛失時: 即失効 → Keychain 項目削除 → `data/` のキャッシュ削除

## E. GO 時に最初に踏む手順（EM が「GO」と言った後だけ）
1. 最小の範囲で 1 回だけ読み取りを試す（Jira 1 プロジェクトの検索 1 件など）。結果は `data/` の外に出さない
2. 取得フィールドが設計どおり（必要項目のみ）か EM が目視
3. 問題なければ範囲を段階拡大。**異常（想定外の書込権限・想定外フィールド・レート制限）が出たら即 NO-GO に戻す**
