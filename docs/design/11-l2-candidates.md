# L2 候補の線引き

状態: **確定（EM 決定 2026-10-03: Q-014=b）。L2 は当面 0 件、全アクション L1。05 §1 の「`reversible: false` は L1 止まり」に例外は設けない。** 以下の候補分類は、将来 EM が方針を変えるときの材料として残す（C1 を使うには 05 への例外追加が前提）。

旧: ドラフト（emh-014）。**現フェーズは L1。ここは「将来 EM が付与を検討するときの材料」であり、有効化しない。** 付与は EM が [policy/delegation.yaml](../../policy/delegation.yaml) に自分でコミットする。

## 1. 結論
- L2 候補は **1件だけ**: 定型リマインドの Slack 送信（テンプレ固定 + 宛先固定）。ただし現行ポリシー（可逆でないものは L1 止まり）では成立せず、例外の可否を EM が決める（§2・Q-014）。それ以外は L1 のまま（候補外・保留・不可に分類）
- 「自分のタスクのステータス更新」は **Jira の状態遷移にあたるため、EM 決定済みの永続 L1（Q-005）に抵触する**。候補から外した
- 「既決事項の議事録共有」は、本文を秘書が書く時点で自由文。L2 にせず、承認キューの一括確認で負荷を下げる

## 2. 判断の物差し（4問）
どれか1つでも「いいえ」なら L2 候補にしない。

| 問 | 「はい」の条件 |
|---|---|
| 可逆性 | 受け手に通知が届かずに戻せる（`reversible: true`）。Slack 送信は通知が残るので原則 false |
| 影響範囲 | 宛先が固定の小さな集合（自分 / 自チームのチャンネル）。上長・他部門を含まない |
| 内容の機微 | 本文がテンプレで固定され、`sensitivity` が `none` で確定できる（秘書の自由文を含まない） |
| なりすまし感 | 受け手が「EM 本人が書いた」と誤解しても害が出ない（定型の事務連絡） |

**注意（05 との矛盾）**: [05 §1](05-approval-and-audit.md) の判定順 4 は「`reversible: false` は L1 止まり」。Slack 送信は常に `reversible: false` なので、**現行ポリシーのままでは C1 も L2 になれない**。C1 を成立させるには、`reversible: false` でも「テンプレ固定・宛先固定・上限付き」の grant だけ許す例外を 05 / policy に足す必要があり、これは EM の判断（Q-014）。

| ID | アクション（架空例） | 可逆 | 範囲 | 内容 | なりすまし | 分類 |

## 4. C1 を付与する場合の条件（EM が追記する前提の雛形）
```yaml
# 例（架空。コメントアウトのまま repo には入れない）
- action: slack.send
  max_level: L2
  scope: { template_id: daily-reminder-v1, recipients: [team-channel-example] }
  until: <付与日から30日以内>
  daily_limit: 1
  shadow_runs: 5
```
- 付与前に必須: policy lint（emh-022）、`policy/KILL` の動作確認、影子運用 5 件（L1 のまま並走し、EM が送った文面と秘書の下書きが一致するか確認）
- 提案条件（秘書が昇格を「提案」できる目安。付与は EM のみ）: 直近 14 日で 5 件以上、無修正採用率が高い、かつ確認時間が極端に短くない（ゴム印でない）。閾値は運用で調整
- 取り消し: policy の1行を戻す、または `policy/KILL`
