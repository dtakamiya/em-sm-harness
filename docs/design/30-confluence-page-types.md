# Confluence ページ種別ごとの取り込み価値と要約観点

**結論**: Confluence ページは 5 種別（議事録・レトロ・仕様・意思決定記録・報告資料）に分け、種別ごとに「何を落とさず抽出するか」を決める。**初期の取り込み対象は議事録とレトロだけ**（Q-002 回答済み）。残り 3 種別は「将来候補・現状は取得しない」として観点だけ先に固めておく。抽出の形は [28](28-meeting-notes-input.md) の `items` / `excluded`（全行を振り分ける）に統一し、新しい第 3 の形は作らない。

状態: ドラフト（設計のみ・emh-012＝board 上の本件の項目 ID）。Confluence へは接続も書き込みもしない（L1＝秘書は下書きまで・書き込みや送信はしない権限段階）。サンプルはすべて架空（`member-a` / `EX-123` / `ex-space`）。会社固有情報は書かず、`config/local.*` に置く。
位置づけ: [02 §6](02-confluence-input.md)（共通の出力形）の「種別ごとの抽出観点」を埋める文書。取得方式は [02](02-confluence-input.md)、保存は [06](06-cache-schema.md)、機械変換と LLM 抽出の境界は [07](07-fetcher-boundary.md) を正とする。

## 1. 種別の判定と対象範囲
| 種別 | 判定ラベル（例・架空） | 現状 | 根拠 |
|---|---|---|---|
| 議事録 | `ex-minutes` | **取り込む（初期対象）** | Q-002 |
| レトロ | `ex-retro` | **取り込む（初期対象）** | Q-002 |
| 仕様 | `ex-spec` | 取得しない（将来候補） | Q-002 で後回し |
| 意思決定記録 | `ex-decision` | 取得しない（将来候補） | 同上 |
| 報告資料 | `ex-report` | 取得しない（将来候補） | 同上 |

- **判定はラベルで決定的に行う**（LLM に種別を推定させない。[07](07-fetcher-boundary.md)）。ラベルの対応表は `config/local.*` に置く。キー名・雛形への追加は後続（[20](20-config-and-policy-keys.md) と雛形の両方を同時に更新する必要があるため、本書では足さない）
- 複数の種別ラベルが付いたページ、種別ラベルが無いページは `unknown`。**抽出せず**、`notes` に「種別不明のため未抽出」と 1 行残す
- **対象ページが 1 件も無くてもエラーにしない**（Q-002 の付帯条件）。出力は「該当ページなし（議事録・レトロ）」の 1 行で終える
- 将来候補の 3 種別を有効にするのは、EM が種別を明示して追加したときだけ。有効化の判断は EM（§8 未決 1）

## 2. 抽出の共通ルール（全種別）
1. **形は 28 に従う**。ページ本文（[02 §5](02-confluence-input.md) で Markdown 化済み）の見出し以外の全行を `items` か `excluded`（理由つき）に振り分ける。`items` の `kind` / `evidence`（行番号 + 40 字以内の引用）/ `confidence` は [28 §3](28-meeting-notes-input.md) と同じ
2. **02 §6 の配列は 28 の `items` から導出する**（二重に抽出しない）。対応は次のとおり

| 02 §6 の配列 | 導出元（28 の `items`） |
|---|---|
| `decisions[]` | `kind: decision` |
| `open_items[]` | `kind: open_question` |
| `owners[]` / `deadlines[]` | `kind: action_item` の `owner` / `due_raw` |
| `jira_keys[]` | 本文の正規表現一致（02 §6 の式。キー形式の一致のみ） |

3. **種別固有の `kind` は追加しない**。種別ごとの違いは §3〜§7 の「抽出の目印」と「落としてはいけないもの」で表す。例外は §7（意思決定記録）の `status`（`decision` の補助項目）だけ
4. **原文にないことを補わない**。担当・期限・理由は読めたものだけを書く。読めなければ空にして `notes` に理由を残す
5. **担当が読めない場合**: Confluence のメンションは `@[user]` に置換され表示名を持たない（[02 §5](02-confluence-input.md)）。担当が `@[user]` だけで特定できないときは、28 §3 と同じく `owner: null`・`to_em: false`・`confidence: low` で残す（タスク候補には流さない）
6. **出典を必ず付ける**: `source`（`page_id` / `version` / `url`）。出典なしの数字・決定は出さない（[14](14-output-quality-checklist.md) B2）
7. **人に関する抽出は観察のみ**。発言・行動の表現そのままにとどめ、評価語・因果語・属性での括りを使わない（14 B・D）。個人別の時系列は作らない

## 3. 議事録（初期対象）
- **取り込み価値**: 決定・アクション・未決が 1 か所に集まっており、EM 個人のタスクと waiting-for（相手待ち）の主な出所になる。落とすと「言った・聞いていない」の確認コストが EM に戻る
- **抽出の目印**: 「決定」「アクション」「TODO」見出し配下、`- [ ]` のタスクリスト（担当・期限メンションは本文文字列として残る。02 §5）、「決まった」「〜に回す」「確認中」
- **落としてはいけないもの**: 決定事項（承認者・承認の状態）／アクションの担当と期限（原文のまま `due_raw`）／未決事項と確認先／次回までの宿題
- **突合**: 本文の課題キー（`EX-123`）→ Jira キャッシュで実在・現在の状態を確認し、ページ上の「完了」と Jira の状態が食い違うときは **差分として並べるだけ**で、どちらが正しいかを断定しない。Slack 貼り付けの依頼（[13](13-slack-paste-input.md)）と同じ内容のアクションは、重複候補として 1 件にまとめて提示（`source_ref` 同一でなければ「重複の疑い」止まり。[04「取り込みとタスク候補」](04-personal-tasks.md)）
- **抽出しない**: 雑談・次回日程だけの行・確約でない発言（`excluded` に理由つきで残す）

## 4. レトロ（初期対象）
- **取り込み価値**: チームが挙げた課題と試すことの記録。EM が次回レトロの進行案と 1on1 の話題を作るときの材料
- **抽出の目印**: KPT（Keep / Problem / Try）などの見出し配下、「次回試す」「改善案」
- **落としてはいけないもの**: Try（試すこと）の担当・期限・振り返り時期／前回の Try の結果の記載／未決の論点
- **扱い方**
  - Try は `action_item` として残す（EM 本人宛てだけがタスク候補になる。他メンバー宛ては [18](18-proactive-detection.md) の入力）
  - Problem は「挙がっていた」という観察として残し、**原因として書かない**（14 C1）。発生時期が重なる Jira の動きがあっても「共起」と書き、確認方法（誰に何を聞くか）を添える
  - 感情の兆候（`signal`）は抽出しない（[28 §4](28-meeting-notes-input.md) と同じ。公式記録に近く、背景が欠けて誤読しやすい）
  - 個人別の発言数・Problem の件数など、個人別の集計・時系列は作らない（14 D3）
- **突合**: Try の課題キー → Jira の現在の状態。Slack の同時期のやり取りとは**共起として併記**し、関連を断定しない
- **抽出しない**: 個人の評価・人事に触れる記述（ページごとスキップ。[13 §8](13-slack-paste-input.md) と同じ）

## 5. 仕様（将来候補・現状は取得しない）
- **取り込み価値**: 「いつ・何が変わったか」と、Jira 課題との対応。EM が見積もりの前提や依存を確認するとき
- **抽出するもの**: 版と更新日／要件の変更点／未決の仕様論点／参照している課題キー
- **落としてはいけないもの**: 前提・制約・対象外の記載。これらが抜けると、後で「仕様どおり」の判断を誤る
- **突合**: 仕様ページの課題キーと Jira の状態。仕様の版が課題の着手後に更新されたことは**事実として並べる**（因果は書かない）
- **注意**: 本文が長い。全文の要約はせず、変更点・未決・課題キーに絞る（60 秒で読めること。14 A）

## 6. 報告資料（将来候補・現状は取得しない）
- **取り込み価値**: ステークホルダーに出した数字と説明。EM が「前回こう報告した」を一貫して引くときの基準
- **抽出するもの**: 報告日／報告した数字とその出典／報告時点の判断と次の約束
- **落としてはいけないもの**: 数字の定義（何を数えたか）と期間。ここが欠けると比較を誤る
- **扱い方**: ページ上の数字を**秘書側で再計算しない**。Jira 指標（[22](22-jira-metrics-catalog.md)）と食い違うときは、両方を出典つきで並べ、指標の限界（サンプル数・期間）を 1 行添える（14 C3）。約束（新規コミット）は EM の判断事項として別欄に出す（14 E2）
- **突合**: 報告時点の Jira の状態（キャッシュにある範囲のみ。TTL 14 日を超えた分は「確認できない」と書く）

## 7. 意思決定記録（将来候補・現状は取得しない）
- **取り込み価値**: 過去の決定の理由と、現在も有効かの判断。EM が決定を引くとき、古い決定を現行と誤読しないため
- **抽出するもの**: 決定内容／**状態**（提案中・採択・置き換え済み・却下のいずれか。ページの記載がそのまま）／決定日／置き換え先（記載があれば）
- **落としてはいけないもの**: 状態と置き換え先。`status: superseded`（置き換え済み）のページは、現行の決定として出さない
- **`status` の扱い**: `decision` の補助項目として 1 つだけ追加する。ページに状態の記載が無いときは `null`・`confidence: medium` で残し、「採択済み」と断定しない（28 §3 の「承認を確認中」と同じ考え方）
- **理由・代替案**: 原文の記載を引用で残す。秘書が理由を推測して補わない
- **突合**: 決定が参照する課題キーと Jira の状態。決定日以降の Jira の動きは事実として並べるだけ

## 9. 受け入れ基準と検証
**テストの範囲**: 架空の抽出例（§10）の形式・自己整合のみ。ページからの自動抽出は未実装。
- 議事録・レトロ・（将来）仕様・意思決定記録・報告資料の 5 種別すべてに「取り込み価値・抽出の目印・落としてはいけないもの・突合」が書かれている
- 初期対象が議事録・レトロだけで、Q-002 と矛盾しない
- 02 §6 の配列と 28 の `items` の対応が §2 に 1 か所だけある（二重定義がない）
- 14 のブロック項目（B1・B3・B4・C1・D・E）に反する記述がない（因果を断定しない・個人別集計なし・「送った」と書かない）
- 実名・会社固有値・実 URL がない

用語: 検証対象の `items` / `excluded` = 28 の構造化出力（抽出した行と、除外理由つきで残した行）。`@[user]` = Confluence のユーザーメンションを表示名なしで置き換えた表記。

## 10. 抽出例（すべて架空）
**入力**（議事録ページ `ex-minutes`、Markdown 化済み・6 行・見出しも数える）
```
## 決定
- EX-123 は次スプリントに回す（member-a 承認）
## アクション
- @[user]: 手順書を更新
- member-b: デモ環境を 2026-10-09 までに確認
- 次回は来週
```
**出力**（抜粋）
```json
{ "source": { "page_id": "p-001", "version": 3, "url": "https://ex-space.example/p-001" },
  "items": [
    { "id": "c-01", "kind": "decision", "decided_by": ["member-a"], "jira_keys": ["EX-123"],
      "observation": "EX-123 を次スプリントに回す、とページにある",
      "evidence": { "line": 2, "quote": "EX-123 は次スプリントに回す" }, "confidence": "high" },
    { "id": "c-02", "kind": "action_item", "owner": null, "to_em": false, "due_raw": null,
      "observation": "手順書を更新する、とページにあるが担当が読めない",
      "evidence": { "line": 4, "quote": "手順書を更新" }, "confidence": "low" },
    { "id": "c-03", "kind": "action_item", "owner": "member-b", "to_em": false,
      "due_raw": "2026-10-09",
      "observation": "member-b がデモ環境を確認する、とページにある",
      "evidence": { "line": 5, "quote": "デモ環境を 2026-10-09 までに確認" }, "confidence": "high" } ],
  "excluded": [ { "line": 6, "reason": "次回日程のみ" } ],
  "notes": [] }
```
- 担当が `@[user]` だけの行（c-02）は落とさず、`owner: null`・`low` で残す。タスク候補には流さない
- 次回日程だけの行は `excluded` に理由つきで残す（黙って捨てない）
- 突合の例: `EX-123` が Jira キャッシュで完了なら、「ページは『次スプリントに回す』、Jira は『完了』（キャッシュ取得日付き）」と**差分を並べる**。どちらが正しいかは書かない。確認: 担当に一言

仕様・意思決定記録・報告資料の抽出例は、有効化の判断（§8 未決 1）の後に追加する（現状は取得しないため）。
