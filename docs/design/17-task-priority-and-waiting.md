# 個人タスクの優先順位づけと waiting-for 追跡ルール

状態: 確定案（emh-016）。[04](04-personal-tasks.md) の仮置き値を置き換え、[15](15-morning-plan.md) の暫定ルールを確定する。数値は EM の使用感で調整する前提（Q-019 / Q-020）。

## 結論
- 並べ順は **「期限の帯 → 優先度 → 他を止めているか → 期限の近さ」** の 4 段。点数化しない（EM が順序の理由を一目で追える）
- 返信待ちの催促は **3 営業日後に 1 回目、以降 2 営業日ごと**。**3 回目で EM に判断を求める**（催促を増やさない）
- 秘書は並べて見せるだけ。優先度の最終決定と催促の送信は EM（L1）

## 1. 並べ順（4 段・上から優先）
| 段 | 内容 | 補足 |
|---|---|---|
| 1 期限の帯 | 超過 → 今日 → 3 日以内 → それ以外（期限なし） | `due` は外部期限のみ（[04](04-personal-tasks.md)） |
| 2 優先度 | `now` → `soon` → `later` | EM が付けた値。未設定は `soon` |
| 3 止めている数 | `blocks` が多い方を先に | `blocks` の参照先が open/doing/waiting のものだけ数える（完了済みは数えない） |
| 4 期限の近さ・id | 期限が近い順、最後は id | 同点で順序が揺れないように |

- **点数・重み付けはしない**: 重みの根拠を説明できず、EM が納得しにくい。帯の境界（3 日）だけが調整点
- `priority: now` は **同時に 3 件まで**を目安にする。4 件目を付けるとき、秘書は「どれかを soon に下げますか」と 1 回だけ聞く（強制しない）
- 「重要 / 緊急」の 2 軸は持たない。期限＝緊急、priority＝重要、で既存の 2 項目に対応させる（入力項目を増やさない）
- 上位 5 件表示・超過分は件数のみ（[15](15-morning-plan.md) のまま）

## 2. waiting-for（返信待ち）追跡
| 回 | `next_check` の既定 | 秘書の動き |
|---|---|---|
| 登録時 | 3 営業日後 | `waiting_on`（匿名ハンドル）と `next_check` を必須入力 |
| 1 回目の催促 | 到来日に候補へ出す | 催促の**下書き**を用意。送信は EM。送ったら `history` に `nudge` を記録し 2 営業日後へ |
| 2 回目 | 2 営業日後 | 同上。文面は 1 回目より短く、依頼内容を再掲 |
| 3 回目 | — | 下書きを出さず**判断依頼**: A) 直接話す・別経路で聞く B) 別の人に振る / drop。おすすめ: A。期限: 今週中 |

- 営業日 = 土日を除く（祝日は考慮しない。1 日ずれても害が小さいため）。祝日対応は EM が必要と言ってから
- 期限が近い（`blocks` で他を止めている / 3 日以内に自分の期限がある）タスクは、1 回目を **1 営業日後**に短縮してよい。ただし短縮は秘書が提案し EM が承認
- 催促候補は 1 回の計画に**最大 3 件**。超えた分は「ほか N 件」（通知過多を避ける。件数の根拠は [14](14-output-quality-checklist.md) A の 60 秒）
- 待たせている相手を評価する書き方はしない（「遅い」「放置」等は使わず、「N 営業日 返信なし」の事実のみ）
- 返信が来たら EM の一言で `resume`。秘書が返信を自動検知することはしない（Slack 実接続前のため）

## 3. 夕の棚卸しの問い
1 タスク 1 行・選択肢は keep / defer / drop（[04](04-personal-tasks.md) のまま）。対象は次の 3 種だけ:
1. 期限超過（理由は推測せず、超過日数だけ示す）
2. 14 日動きなし（`updated` と `history` の最終操作日から）
3. 3 回以上 defer したもの（drop か分割を問う）

1 回の棚卸しで問うのは**最大 5 件**。残りは翌日に繰り越す（問いすぎない）。

## 4. 実装への反映（本 PR）
- `scripts/morning_plan.py` の並べ順に 3 段目（`blocks` の数）を追加。他は 15 の暫定ルールと同じ
- 催促回数は**数える側のみ**実装済み（`history` の `op: nudge` を読む。`morning_plan.py` の `_nudge_count` = 催促回数を数える内部関数）。登録（`待ち t-0001 member-a`、[24](24-reply-apply.md)）は実装済み。`nudge` を `history` に**書く側は未実装**（`apply_reply.py` に該当操作なし）。3 回 defer の問い（朝夕の計画の内部名 `defer_asks` = 先送り3回目の判断依頼候補。[25](25-evening-wrapup.md)）は実装済み。営業日計算と、期限超過・14 日動きなしの棚卸しは未実装（本書が仕様）

## 5. 受け入れ基準
- 同じ入力で並べ順が常に同一（決定的）
- `blocks` が多いタスクが、同じ帯・同じ優先度の中で先に来る
- 完了済みタスクを指す `blocks` は数えない
