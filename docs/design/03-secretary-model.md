# 秘書モデルと委任ラダー（初版ドラフト）

状態: ドラフト。現フェーズは **L1（下書きまで）**。

## 位置づけ
このハーネスは、多忙な EM に代わって EM 業務・SM 業務を進める「秘書」。
EM が見るのは「何を決めるか」だけ、という状態を目指す。準備・整理・下書き・段取りは秘書が済ませる。

## 秘書の5つの仕事
1. **集める**: Jira / Confluence（読み取り）・Slack 貼り付けを取り込み、構造化する
2. **管理する**: EM の個人タスク（[04-personal-tasks.md](04-personal-tasks.md)）
3. **先回りする**: 期限接近・ブロッカー・返信待ち・準備が要る会議・放置チケットを、言われる前に拾う
4. **下書きする**: Slack 返信案 / Jira コメント案 / 議事録 / レトロ進行案 / 1on1 アジェンダ / ステークホルダー報告 / スプリント状況サマリ
5. **判断材料を整える**: 決めることは「選択肢2つ以内 + おすすめ + 期限」で提示

## 委任ラダー

| レベル | できること | 現在 |
|---|---|---|
| L0 観察・報告 | 取り込み・要約・提示のみ | 有効 |
| L1 下書き | 返信・コメント・資料の下書きを作る。**送信・更新は EM 本人** | 有効（現フェーズの上限） |
| L2 代行実行 | 事前承認ルールの範囲で、秘書が Jira / Confluence / Slack に書き込む・送る | **無効**（EM の明示 GO + アクション種別ごとの付与が必要） |

### 常に EM 本人（L2 付与不可）
人事評価・懲戒・報酬・採用判断 / 1on1 の機微な内容の共有 / 上長・他部門への新規の約束・コミット。
これらは下書き・材料整理までで、判断も実行も EM。

## アクションのデータ表現（L2 を後から安全に足すため）
秘書の「やること」は、実行せず次の形のデータとして出力する:

```json
{ "action": "jira.comment", "target": "ABC-123", "content": "...", "level_required": "L1",
  "reversible": true, "audience": "team", "rationale": "..." }
```
- `action` 種別ごとに委任ポリシー（`policy/delegation.yaml`、EM が編集）で可否を判定
- 現フェーズは全アクションが「下書きとして EM に提示」で終わる
- 将来 L2 を付与する場合も: ドライラン → 差分表示 → 実行 → 監査ログ（`data/audit/`）。取り消せないものは L2 にしない

## L2 候補の考え方（emh-014 で詰める）
低リスク・可逆・影響範囲が自分/小さい: 自分のタスクの更新、定型の日程調整、既決事項の議事録共有 など。
判断基準は「リスク / 可逆性 / 影響範囲 / なりすまし感」。付与は EM が種別ごとに明示する。

## EM の認知負荷を下げる出力ルール
- 60秒で読める。結論 → 要対応 → 詳細
- 通知は絞る。緊急度の低いものは朝夕にまとめる
- 判断依頼は「選択肢2つ以内 + おすすめ + 期限」
- 事実と解釈を分ける。人の評価・感情は断定しない
