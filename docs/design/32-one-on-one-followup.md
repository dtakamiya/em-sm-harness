# 1on1 前回アクションの追跡（O2・試作の仕様）

状態: 試作（emh-052。改善ループ提案を管理する部門ボードの項目番号）。tasks だけで動く。サンプルは全て架空。
用語: **O2** = [12](12-secretary-job-list.md) §3.3 の仕事番号（前回アクションの追跡）/ **L0** = 読み取り専用（[03](03-secretary-model.md) の委任ラダーの最下段）/ **Q-017** = 感情の兆候を扱うときの条件（個人別の集計・時系列を作らない。[open-questions](open-questions.md)）/ **EM** = Engineering Manager（このハーネスの使い手）

## 結論
- 1on1 の準備で「前回の約束がどうなったか」を、EM の記憶頼みにせず 1 枚で見られる: `scripts/one_on_one_followup.py`（L0）
- **tasks のスキーマは変えない**。前回の約束との紐付けは既存の `source_ref`（前回の 1on1 メモ名）と `waiting_on`（相手の匿名ハンドル）だけで行う（[04](04-personal-tasks.md)）
- 前回の 1on1 日・対象は**実行のたびに EM が渡し、保存しない**。保存すると個人別の時系列になり Q-017 に反する
- 観察のみ。理由の推測・評価語・人別の比較は出さない

## 入力
| 引数 | 内容 |
|---|---|
| `--since` | 前回の 1on1 の日（必須）。前回より前に完了済みのものは持ち越しではないので除外し、件数だけ詳細に出す |
| `--ref` / `--member` | どちらか必須。`source_ref` がメモ名と一致、または `waiting_on` がハンドルと一致したタスクだけ拾う。どちらも無いと全タスクを人に紐付けて出してしまうので、何も出さず終了する |
| `--tasks` / `--archive-dir` | 既定 `data/tasks/tasks.json` と、その隣の `archive/`。**完了は 30 日で archive に移る**（[04](04-personal-tasks.md)）ので、月 1 回の 1on1 でも前回分を拾えるよう archive も読む。同じ id は tasks.json を優先 |

前提: 1on1 で決まった約束は、メモの取り込み時に `source_ref` を前回メモ名にしてタスク化されていること（[28](28-meeting-notes-input.md)）。**タスク化されていない口頭の約束は拾えない**（出力の詳細にも書く）。

## 出力（標準出力の Markdown 1 枚）
先頭に 🟢/🟡 と結論、次に「EM がやること」。節は未完了（open/doing）・返信待ち・前回以降に完了・中止。各節は最大 5 件、超過は「ほか N 件」。
- 🟡: 未完了または返信待ちが 1 件以上 → 「今回の議題にする / 閉じる」を EM が決める
- 🟢: すべて完了・中止 → 対応不要
- 期限超過は `due` との差の日数のみ。「返信待ちにして N 日」は `wait`/`delegate` の最後の操作日から。記録が無ければ「記録なし」と書く

## 空入力・取れなかったときの挙動
どれも「全部完了」に見えないよう、**記録が見つからない（EM の記憶・前回のメモで確認）** と明示する。

| 状況 | 出力 |
|---|---|
| tasks.json も archive も無い | 🟡「tasks.json が見つかりません」＋ EM の確認依頼 |
| ファイルはあるが該当 0 件 | 🟡「該当するタスクがありません」。タスク化していなければ今回のアジェンダ作成時に起こす |
| `--ref` も `--member` も無い | 何も出さず、指定を求めて終了 |
| `--since` / `--today` が日付でない・JSON が壊れている | 場所つきのメッセージで終了（上書きしない） |

## してはいけないこと（[14](14-output-quality-checklist.md) の B〜D）
- `data/` への書き込み、Slack / Jira / Confluence への書き込み・送信、トークン使用
- 未完了の理由の推測、評価語（遅れ・怠など）、人別の件数比較、個人別の時系列・蓄積

## 受け入れ基準
- 「詳細」を除く本文は 600 字未満・各節は最大 5 件（テストで確認）
- 評価語が出力に含まれない（テストで確認）
- 空入力 3 種・archive 読み込み・前回より前の完了の除外・tasks.json 優先・非破壊・不正入力をテストで固定（`tests/test_one_on_one_followup.py`）
- 試用の確認: EM が次の 1on1 前に 1 回実行し、前回の約束が漏れなく出たか（出なかったものは、タスク化されていなかったのか紐付けが違ったのか）を見る

## 未決・今回やらないこと
- skill 化（`skills/`）と README の日次手順への組み込みは、試用で使えると分かってから別項目にする
- 1on1 アジェンダ案（O1）への組み込みはしない。O1 は本出力を材料に使える
- 前回メモ名の命名規則（`1on1-<ハンドル>-<日付>.md` はサンプル上の仮置き）は、取り込み側の実装時に揃える
