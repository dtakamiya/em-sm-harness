# スプリント健全性チェックの出力テンプレ（emh-008・S1）

状態: ドラフト（設計のみ・実接続なし）。値はすべて架空例。S1 = 秘書の仕事の番号（[12](12-secretary-job-list.md) §3.2）。**emh-008** = この設計の backlog ID。**EM** = エンジニアリングマネージャー（この秘書の利用者）。**complete: false** = Jira キャッシュの取得が途中で切れている印（[06](06-cache-schema.md)）。**H1〜H6** = §6 の検証項目の番号。**14 の A〜E** = [出力品質チェックリスト](14-output-quality-checklist.md)の区分。**SP** = ストーリーポイント（見積もりの相対値）。**N** = 進行中の課題数。

## 結論
- S1 の出力を「状態 1 行 → 観察 → 解釈の候補 → EM がやること」の型に固定した。観察の数字は `scripts/jira_metrics.py`（[22](22-jira-metrics-catalog.md)）の出力を**そのまま貼る**（LLM は数え直さない）
- 状態語は件数だけで決める（§2）。解釈の候補は固定文言から選ぶ（§3）。自由記述にしない
- 範囲は S1 のみ。レトロ準備（S3）・1on1 準備（O1）は別項目（§6）。**1on1 には jira_metrics の数字を使わない**（22 §1）

## 1. 入力と出力の対応
| 出力の枠 | 元 | 備考 |
|---|---|---|
| 状態 + 結論 1 行 | `jira_metrics.py` の件数（更新なし・追加・除外） | §2 の規則。LLM の印象で決めない |
| 観察 | 出力の「観察」行（取得完全性・N・更新なし・スコープ） | 貼り付け。担当者情報は元から出ない |
| 解釈の候補 | §3 の固定文言 | 最大 2 つ。出典は 22 の誤読リスク |
| EM がやること | §3 の確認先 | 任意の一言確認まで。判断依頼は別欄 |
| 限界 | 出力の「限界」行 | 本文は 1 行に縮め、全文は末尾「詳細」へ（14 A2・C3） |

## 2. 状態語の規則（件数のみ）
| 条件 | 状態 | 本文 |
|---|---|---|
| 更新なし 0 件 かつ 追加 0 件 かつ 除外 0 件 | 🟢 | 「検知なし」1 行 + 限界（14 F） |
| 上のどれかが 1 件以上 | 🟡 | 型どおり |
| 進行中 N < 5 | 追加・除外だけで判定 | `jira_metrics.py` は N < 5 のとき更新なしの件数を出さない（22 §1）。**更新なしを 0 件扱いにしない**（「出ていない」であって「0 件」ではない）。観察に「更新なし: 件数が少ないため割合は出さない」が残る |
| `complete: false`（再取得が必要） | 状態語なし | 再取得メッセージだけを出す。指標を推測しない（22 T4） |
| active なスプリントなし | 更新なしの件数だけで 🟢/🟡 | 「スコープは数えない」を観察に残す |

🔴 は S1 では使わない。S1 は材料の提示で、緊急度の判定は EM（S5）。繰り越しは状態語に影響させない（件数は観察に出す）。

## 3. 解釈の候補（固定文言・最大 2）と確認先
| 出す条件 | 候補の文言 | EM がやること（任意） |
|---|---|---|
| 更新なし 1 件以上 | 待ちステータス（レビュー待ち等）で更新が止まっている可能性（22 §2.1） | 該当キーの担当に状況を一言確認 |
| 追加 1 件以上 | 緊急対応、または計画漏れの可能性。Jira から区別できない（22 §2.3） | 追加分の経緯を担当に確認 |
- 両方出るときは「同じスナップショット（取得時点）に両方ある（共起）。関係は未確認」と 1 行足す。原因と書かない
- 除外は「完了で抜けたとは限らない」を限界側に置く。候補には数えない。**除外だけで 🟡 になるとき（更新なし 0 件または N < 5 で非表示、追加 0 件）は解釈の候補を出さない**。「解釈の候補: なし」と 1 行にし、EM がやることは「対応不要」か除外キーの任意確認にする
- 判断が要る事項（スコープ・ゴール変更）は S5 の判断欄へ。選択肢 2 つ以内 + おすすめ + 期限
