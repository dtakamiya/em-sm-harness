# 出力品質チェックリスト（秘書の出力を EM に出す前の受け入れ基準）

状態: ドラフト（emh-009）。em-lead の受け入れ判定と、秘書スキルの自己点検の両方で使う。
対象はハーネスが EM に見せる全出力（今日の計画・下書き・サマリ・判断依頼・承認キュー）。サンプルは全て架空。

## 1. 使い方
- 下の **A〜E を全項目 YES で合格**。1つでも NO なら EM に出さず直す
- 重大度: **ブロック**（出せない）/ **直す**（出す前に修正）。F は注意（合否に入れない）
- 自己点検は出力の末尾に載せない。EM の読む量を増やさないため、合否だけ内部で判定する

## 2. チェック項目

### A. 60 秒で読める
| # | 項目 | 重大度 |
|---|---|---|
| A1 | 1 行目が結論（状態 + 要対応の有無）。経緯・手順から始めない | 直す |
| A2 | 本文が約 600 字・箇条書き 5 項目以内。超える分は末尾「詳細」に分離 | 直す |
| A3 | 「EM がやること」が明示されている（なければ「対応不要」と書く） | 直す |
| A4 | 判断依頼は「選択肢 2 つ以内 + おすすめ + 期限」。判断不要なら「判断不要」と明記 | 直す |
| A5 | ID・略語・内部用語は初出で一言説明。生ログ・生 JSON を貼らない | 直す |

### B. 事実と解釈の分離
| # | 項目 | 重大度 |
|---|---|---|
| B1 | 「観察（事実）」と「解釈の候補」が別の見出し・別の行になっている | ブロック |
| B2 | 事実に出典（チケット ID・日付・貼り付け日）が付く。出典なしの数字は書かない | 直す |
| B3 | 解釈は最大 2 つ・候補として書く（「〜の可能性」「他に〜も考えられる」）。断定しない | ブロック |
| B4 | 事実欄に評価語・推測語（遅い・やる気がない・おそらく）が混ざっていない | ブロック |

### C. 因果と共起
| # | 項目 | 重大度 |
|---|---|---|
| C1 | 「A の後に B」「A と B が同時期」を「A が原因」と書いていない | ブロック |
| C2 | 原因らしきものを書くときは「共起」と明記し、確認方法（誰に何を聞くか）を添える | 直す |
| C3 | 指標の限界（サンプル数・期間・見積もりの粒度）を 1 行で添える（指標系の出力のみ） | 直す |

### D. 人に関する出力（レッテル貼りなし）
| # | 項目 | 重大度 |
|---|---|---|
| D1 | 人を属性で括らない（「遅い人」「疲れている人」「低パフォーマー」など） | ブロック |
| D2 | 観察は本人の発言・行動の表現そのもの（引用または近い言い換え）にとどめる | ブロック |
| D3 | 個人別の時系列・ランキングを作らない（チーム単位か、その場限りの事実） | ブロック |
| D4 | 評価・懲戒・報酬・採用・機微な共有は材料整理までで、結論・推奨を書かない | ブロック |

### E. 委任ラダー・情報の取り扱い
| # | 項目 | 重大度 |
|---|---|---|
| E1 | 「送った」「更新した」と書かない。L1 の出力は「下書き」「案」と明示 | ブロック |
| E2 | 新規コミット（EM の名前での約束・期限）を本文に埋めていない。必要なら EM 判断欄へ | ブロック |
| E3 | 実名・Slack 本文の長い引用・会社固有の値・秘密値が出力・PR に入っていない（配布物の場合） | ブロック |

### F. 注意（合否に入れない）
- 前回と同じ指摘を繰り返していないか（EM が見飽きる）
- 下書きはトーンが EM の口調に近いか（EM が直した箇所を次回に反映）
- 空振りの検知を出していないか。検知ゼロなら「検知なし」の 1 行で済ませる

## 3. 良い例・悪い例（架空）
| 観点 | 悪い例 | 良い例 |
|---|---|---|
| A1 | 「本日の Jira を確認した結果をお知らせします」 | 「🟡 注意: 期限超過 1 件・返信待ち 2 件。EM がやること: 催促案 2 件の確認」 |
| B | 「メンバー X は最近遅く、やる気が落ちている」 | 観察: 「X-12 が 5 日間 In Progress（スプリント平均 2 日）」。解釈の候補: ①見積もりが小さい ②他の割り込み。確認: X-12 の担当に一言 |
| C | 「担当が偏っているのでスプリントが遅れた」 | 「担当が偏っている（共起）。遅れとの因果は未確認。確認: 割り込みの有無を聞く」 |
| D | 「Y は評価が低いので 1on1 で指摘を」 | 「Y に関する観察: 発言 3 件（引用）。評価に関わる判断は EM が行うため材料のみ」 |
| E | 「催促を送信しました」 | 「催促の文面案です（未送信）」 |

## 4. 受け入れ判定の流れ
1. 出力を出す側（スキル・em-builder）が A〜E を自己点検し、合否だけ記録
2. em-lead が **ブロック項目**を重点確認（B1/B3/B4/C1/D/E）。1 つでも NO なら差し戻し
3. 差し戻し理由は項目番号で返す（例: 「B4: 事実欄に推測語」）
4. EM のフィードバック（[feedback-inbox](feedback-inbox.md)）で出た指摘は、該当する項目を追加・修正して本書に反映

## 5. 未決事項
- A2 の「約 600 字」は仮置き。実際の出力を EM に見せて調整する（EM の FB 待ち）
- 検証の自動化（語彙チェックなど）は実出力が増えてから。今は目視 + 項目番号で運用
