# 0003. 先回り検知の仕様（検知ルール・重要度・通知の絞り方）

- 状態: 提案（Ryoko 判定は条件付き GO。EM の Q-021〜Q-023 回答で確定）
- 日付: 2026-10-04
- 関連: emh-017 / [18](../design/18-proactive-detection.md) / [12](../design/12-secretary-job-list.md) D2〜D4・M1 / [15](../design/15-morning-plan.md) / [17](../design/17-task-priority-and-waiting.md)
- 進め方: 設計レビュー会の第1回（別々の案）と第2回（批評）まで実施。集約は本書（実行は 1 セッション内の役割分担）

## 背景・決めること
期限接近・ブロッカー・返信待ち・準備が要る会議・放置チケットを、EM が走らせたコマンドの出力として先回りで出す。決めるのは検知ルール、重要度、まとめ方、通知を絞る仕組み。
制約: L1（下書きまで・外部書き込みなし）/ 実接続なし / 常駐・cron なし / 実データなし / 60 秒で読める（[14](../design/14-output-quality-checklist.md) A）。

## 案
### 案A（出した人: SM アナリスト役）— 認知負荷の視点
- 朝の計画に 1 セクションとして統合。最大 5 件（催促は内数 3）。帯は 🔴 / 🟡 / 参考の 3 つ
- 台帳（ルール + 対象 + 帯が鍵）で、**同じ帯なら再掲しない**。帯が上がった時だけ再掲
- 「出さない」ルール 8 種（既読・スヌーズ・データ鮮度・評価語禁止・土日は出さない 等）
- 懸念: 上限で重要案件が漏れる / 貼り付け依存 / 抑止が強すぎる

### 案B（出した人: ビルダー役）— 決定的・テスト可能の視点
- `scripts/proactive_scan.py` を別コマンドで実行。純関数 5 本 + 固定 3 段 + 状態ファイル。終了コード 0 / 10 / 2
- 同じ key は **2 営業日 cooldown**。低は週 1 の digest。3 回表示で未対応なら判断依頼に昇格
- 入力欠損は「入力なし」1 行で他は続行。JSON 破損のみ中止
- 懸念: 15 と内容が重なる / cooldown・放置 14 日は根拠の薄い仮値

## 批評（互いの案への指摘）
- A への指摘（B 担当から）:
  1. 「期限接近」の入力に Jira の期限を挙げているが、[06](../design/06-cache-schema.md) のスキーマに Jira `due` は無い → tasks の `due` とスプリント終了日（`sprints[].end`）に限る
  2. 台帳が `data/outputs/`（成果物の置き場）にある、「同じ帯なら無期限に再掲しない」は期限超過を隠しうる、「土日は出さない」は EM が週末に走らせたとき無反応になる
  3. 決定的な実装単位（関数・終了コード・冪等性）が無く、テストで確認できない
- B への指摘（A 担当から）:
  1. 返信待ちの「3 回表示で判断依頼」を全ルールに広げると、**期限超過が 3 回で消える**危険がある（17 の 3 回目は催促回数であり表示回数ではない）
  2. 放置を一律 14 日にすると Jira の進行中チケットには遅すぎる（滞留は週内で気づきたい）
  3. 別コマンドだと EM が読む場所が 2 つに増える。入力のデータ鮮度（`fetched_at`）の警告が無い
  4. 放置の出力に担当者を出すと、人を名指しする書き方になりうる

## 決定（em-lead 集約 + Ryoko 判定: 条件付き GO）
**実装は B（決定的スクリプト・状態ファイル）、出し方は A（読む場所は 1 つ・事実のみ・鮮度警告）を採る。**
1. 実装は `scripts/proactive_scan.py`（純関数 + 状態ファイル）。朝の計画からは「先回り」節として取り込める（出力を読む場所は朝の計画 1 枚）。統合の形は Q-021
2. 重要度は固定 3 段（高 / 中 / 低）。点数化しない
3. **高は抑止しない**（期限超過・今日期限・返信待ち 3 回目は、解消するまで毎回出す）。cooldown と 3 回判断依頼への昇格は中・低だけ
4. 放置は Jira 進行中 7 営業日（仮置き・Q-022）、個人タスク 14 日（17 と同じ）
5. 状態は `data/state/proactive.json`（`data/outputs/` ではない）。key と回数だけ持ち、本文・実名を入れない
6. 土日でも EM が走らせたら動く（営業日は日数計算だけに使う）
7. 担当者の識別子は出力しない（「担当: 他メンバー」）。評価語・理由の推測を書かない
- 条件: Q-021〜Q-023 の回答まで実装に入らない。しきい値は全て仮置きで、EM の使用感で調整
