# 下書きテンプレ: レトロ進行案（EM/SM 向け）

分類: 下書き（L1）。入力: スプリント状況サマリ・前回レトロの Try・Jira キャッシュ（[06](../../docs/design/06-cache-schema.md)）。進行と投稿は EM。**個人の評価・犯人探しの場にしない**（人ではなく仕組みを話す）。

## 必須項目
- 冒頭 `【下書き・未送信】` + 所要時間と目的 1 行
- 議論の材料: 観察（事実）と解釈の候補（最大 2）を別見出しに。出典と集計日を付ける
- 観察の中に「指標:」枠（任意）: `scripts/jira_metrics.py` の「観察」行を**そのまま貼る**（先頭の試作バナー行は除く。数え直し・言い換えをしない）。キャッシュが無い・`complete: false` のときは枠ごと省き、再取得が必要と書く。限界行は本文に入れず末尾「詳細」に回す。SP はストーリーポイント（見積もり）、「SP なし」は見積もり未入力。サンプル行に初見の語があれば末尾に 1 行注記する。担当者別の並びは出さない（[22](../../docs/design/22-jira-metrics-catalog.md) §2.5）。**1on1 には流用しない**
- 前回 Try の振り返り（やった/やらなかった/効果は未確認、のいずれか）
- 進行の時間配分（合計が所要時間に収まる）と、各パートの問い 1 つ
- 次回に持ち越す Try の候補（最大 3）。採否と担当・期限は `⟦EM が決める⟧`

## テンプレ
```
【下書き・未送信】スプリント{N}レトロ（{分}分）: 目的 = {1行}
材料: {日付}時点（出典: キャッシュ {取得日}、{件数}件）

■ 前回の Try
- {Try}: {実施済み|未実施|効果は未確認}

■ 観察（事実）
- {チケット単位・状態・日数。個人名は伏せる}
指標: {jira_metrics.py の観察行をそのまま貼る。任意}

■ 解釈の候補（断定しない）
① {候補}の可能性 → 場で確認: {問い}
② {候補}の可能性 → 場で確認: {問い}
（共起を原因として書かない）

■ 進行
- {分}分 チェックイン: {問い}
- {分}分 振り返り（良かった/課題）: {問い}
- {分}分 Try 決め: {問い}

■ Try 候補（最大3）
- {案}

⟦EM が決める⟧
- Try の採否・担当・期限（選択肢2つ以内 + おすすめ + 期限）

詳細（限界）: {jira_metrics.py の限界行。指標を貼ったときのみ。末尾に置く}
```

## EM が直す手間を減らす工夫
- 材料は事実だけを先に並べ、解釈は場で確認する問いの形にする（結論を持ち込まない）
- 個人名を出さず、チケット ID と状態で書く。発言の促し方は EM が決める
- Try は「誰が・いつまでに」を空欄にして EM に委ねる（新規コミット防止）
- 全体 600 字以内（スプリント状況サマリと同じ上限）。時間配分は合計を明記し、EM が削るだけで済む形にする

## 匿名化サンプル（架空）
```
【下書き・未送信】スプリント12レトロ（45分）: 目的 = レビュー待ちの滞留を減らす案を決める
材料: 2026-10-09 時点（出典: キャッシュ 10/9）

■ 前回の Try
- 朝のレビュー枠: 効果は未確認

■ 観察（事実）
- EX-103: レビュー依頼から 3 日経過（指標の更新なし対象外）
指標: 観察（ex-proj・2026-10-09・進行中 N=7（N=対象の課題数）・取得: 完全）
- 更新なし: 進行中 7 件のうち 2 件が 7 営業日以上更新なし（EX-101, EX-102）
- スコープ（Sprint 11）: 開始後に追加 1 件（計 0 SP）（SP なし 1 件は除外）
  除外 1 件（計 0 SP）
  繰り越し 1 件（計 3 SP）

■ 解釈の候補（断定しない）
① レビュー待ちが偏った可能性 → 場で確認: 待ち時間の体感
（追加と更新なしは共起。関係は未確認）

■ 進行
- 10分 チェックイン / 20分 振り返り / 15分 Try 決め

■ Try 候補
- レビュー依頼の通知ルール

⟦EM が決める⟧
- Try の採否・担当・期限（A: 1件に絞る / B: 2件。おすすめ A、レトロ終了時まで）

詳細（限界）: 更新なしは updated 基準の営業日。追加の経緯は Jira から分からない（確認先: 担当者）。
注記: SP = ストーリーポイント（見積もり）。「SP なし」は見積もり未入力。
```
