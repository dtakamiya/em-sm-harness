# 下書きテンプレ: 催促（返信待ちの確認）案

分類: 下書き（L1）。**送るのは EM**（秘書は送らない）。入力: `waiting` タスク（[04](../../docs/design/04-personal-tasks.md)・[17](../../docs/design/17-task-priority-and-waiting.md)）。朝の計画の「返信待ちの催促候補」から作る。

## 必須項目
- 冒頭に `【下書き・未送信】`
- 催促の型（初回の確認 / 再確認）を 1 つ選んで先頭に明示。3 回目以降は下書きを出さず判断依頼に回る（17 §2）
- 対象タスク id と相手の匿名ハンドル、根拠にした事実（確認予定日・催促済み回数）
- 本文 **最大 2 案**（案A 短く / 案B 丁寧に）。問いは **1 件 1 問**
- `⟦EM が決める⟧` 欄: 次の確認予定日・期限・担当変更など新規コミットになる箇所（本文には入れない）

## テンプレ
```
【下書き・未送信】催促の型: {初回の確認|再確認}
対象: {タスク id}（相手: {匿名ハンドル}）
観察: {何の返答待ちか / 確認予定日 / 催促済み回数}

■ 案A（短く）
{問い 1 文}

■ 案B（丁寧に）
{宛名}さん、{一言}。{問い 1 文}。{判断に使う補足 1 文}

⟦EM が決める⟧
- {次の確認予定日などのうち本文に入れなかった項目と、おすすめ 1 つ}
```

## EM が直す手間を減らす工夫
- 「遅れている」と断定せず、観察（確認予定日・催促済み回数）だけを書き、状況は問いで聞く
- 約束・催促になる語（「〜までにお願いします」）は本文に入れず ⟦EM が決める⟧ に寄せる
- 人への評価に読める言い回しを避け、タスクの状態を主語にする
- 再確認では前回との差（前回から N 日）を観察に 1 行足し、同じ文面の繰り返しを避ける

## 匿名化サンプル（架空）
```
【下書き・未送信】催促の型: 初回の確認
対象: t-0002（相手: member-c）
観察: staging データ準備の返答待ち。確認予定は 2026-10-08、催促は 0 回済み

■ 案A（短く）
staging データの準備は進んでいますか。状況を教えてください。

■ 案B（丁寧に）
member-c さん、お疲れさまです。staging データの準備について、現在の状況を教えてください。難しい点があれば合わせて共有ください。

⟦EM が決める⟧
- 次の確認予定日（おすすめ: 返答を見てから決める）
```
