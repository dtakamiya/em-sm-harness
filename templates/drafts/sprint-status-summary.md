# 下書きテンプレ: スプリント状況サマリ（チーム向け）

分類: 下書き（L1）。入力: Jira キャッシュ（[06](../../docs/design/06-cache-schema.md)）。投稿は EM。チーム全体に出すため**個人名・個人別の一覧を載せない**。

## 必須項目
- 冒頭 `【下書き・未送信】` + 状態 1 語（🟢順調/🟡注意/🔴要対応）と結論 1 行
- 残日数・完了/残ポイント（`scripts/jira_metrics.py` の「進捗」行をそのまま写す。計画ポイント・達成率は出さない）など数字（集計日・出典 JQL 範囲）。出典なしの数字は書かない
- 観察（事実）と解釈の候補（最大 2）を別見出しに
- 指標の限界 1 行（サンプル数・見積もりの粒度）
- チームへのお願い（具体 1〜2 点）。判断が要る事項は EM 判断欄へ

## テンプレ
```
【下書き・未送信】{🟢|🟡|🔴} スプリント{N}・残り{日数}日: {結論1行}
集計: {日付}時点（出典: キャッシュ {取得日}、{件数}件）

■ 観察（事実）
- 完了 {x}pt / 残 {y}pt（未見積もり {n} 件は除外）
- {滞留チケット}: {N}日間 {ステータス}（担当は伏せる）
- スコープ変動: 追加 {a}件 / 除外 {b}件

■ 解釈の候補（断定しない）
① {候補}の可能性 → 確認: {方法}
② {候補}の可能性 → 確認: {方法}
（共起を原因として書かない。因果は未確認）

■ 指標の限界
{件数・期間・見積もり粒度}

■ チームへのお願い
- {具体的な依頼 1〜2 点。期限は ⟦EM が決める⟧}

⟦EM が決める⟧
- {スコープ/ゴール変更など判断が要る事項: 選択肢2つ以内 + おすすめ + 期限}
```

## EM が直す手間を減らす工夫
- 結論 1 行を貼るだけで足りるように、本文はその根拠にとどめる（600 字以内）
- 個人名を出さず、チケット ID と状態で書く。EM は担当への声かけ有無だけ判断する
- お願いの期限は空欄にして EM が入れる（新規コミット防止）
- ポイントが全件で埋まっていない場合は集計から外さず「未見積もり n 件」を明記

## 匿名化サンプル（架空）
```
【下書き・未送信】🟡 スプリント12・残り3日: 完了 21pt・残 14pt。滞留 2 件の確認をお願いしたい
集計: 2026-10-08 時点（出典: キャッシュ 10/8、18件）

■ 観察（事実）
- 完了 21pt / 残 14pt（未見積もり 2 件は除外）
- EX-12: 5日間 In Progress、EX-15: 4日間 In Review
- スコープ変動: 追加 2件 / 除外 0件

■ 解釈の候補（断定しない）
① レビュー待ちが滞留している可能性 → 確認: レビュアーの空き状況
② 追加 2 件でスプリントが窮屈になった可能性 → 確認: 追加の経緯
（追加と滞留は同時期＝共起。関係は未確認）

■ 指標の限界
18 件・1 スプリント分のみ。ポイントは 2 件未見積もり。

■ チームへのお願い
- EX-15 のレビュー担当は今日中にひとこと状況を（期限は EM が確定）

⟦EM が決める⟧
- スコープ調整の要否（A: 現状維持 / B: 追加分を次回へ。おすすめ A、明日のデイリーまで）
```
